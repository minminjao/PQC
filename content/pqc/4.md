# 국산 알고리즘 KpqC

## KpqC 공모전

국가정보원과 국가보안기술연구소가 주관한 한국형 양자내성암호(KpqC) 공모전은 NIST와 별도로 **국산 알고리즘 자체 표준**을 확보한 독자 트랙입니다.

| 시기 | 진행 |
|---|---|
| 2021.5 | 공모전 발족 |
| 2021.11 | 공모 개시, 16종 접수 |
| 1라운드 | 8종 선정 |
| 2라운드 | 정밀 검증 |
| 2025.1 | 최종 4종 선정 |

| 용도 | 선정 알고리즘 |
|---|---|
| 공개키 암호 / 키 교환 (KEM) | **NTRU+**, **SMAUG-T** |
| 전자서명 | **HAETAE**, **AIMer** |

공공 조달의 기준선이 되므로, 국내 공공·금융 시스템을 다룬다면 NIST 표준과 함께 알아 둘 필요가 있습니다.

> 🎛 인터랙티브 — NIST vs KpqC 대응표
> 좌: NIST(ML-KEM, ML-DSA, FN-DSA, SLH-DSA), 우: KpqC(NTRU+, SMAUG-T, HAETAE, AIMer). 같은 계열끼리 선으로 연결. 각 노드 클릭 시 아래 절로 스크롤.

## NTRU+ — 1998년 원조를 재설계한 격자 KEM

1998년의 원조 NTRU를 재설계해 **NTT 고속화와 CCA 안전성을 동시에** 확보했습니다.

**암호화 파이프라인**: 평문 m → SOTP 인코딩 → ACWC₂(최악→평균 실패율 전환) → NTRU 암호화(NTT 고속 곱셈) → 암호문 c = hr + m

재암호화 없는 FO⊥ 변환으로 복호화 시 검증 과정을 단순화해 속도를 높였습니다.

### 동일 보안수준 성능 비교 (n≈768급, AVX2 기준)
| | 암호문 | Encaps 비용 |
|---|---|---|
| NTRU+768 | 1,152 B | 80K cycles |
| Kyber-768 | 1,088 B | 256K cycles |
| SMAUG-T192 | 992 B | 205K cycles |

암호문은 조금 크지만 **Encaps 속도는 최대 3배 이상 빠릅니다.** 처음부터 NTT 도메인을 유지해 트렁케이션이 불필요하기 때문입니다.

## SMAUG-T — 경량 디바이스용 격자 KEM

1라운드의 SMAUG와 TiGER를 통합했습니다. **두 개의 서로 다른 격자 문제로 이중 보호**합니다.

- 비밀키 s는 Module-LWE로, 공유키(암호문)는 Module-LWR로 각각 보호
- FO 변환으로 최상위 보안성(IND-CCA2) 확보
- 복호화 시 오류 제어로 정확성 보장

### 보안 레벨별 공개키 크기
| 파라미터 | 공개키 |
|---|---|
| TiMER (IoT) | 672 B |
| SMAUG-T128 | 672 B |
| SMAUG-T192 | 1,088 B |
| SMAUG-T256 | 1,792 B |

### 부채널 대응 — Fisher-Yates 하이딩
1라운드에서 상수시간 가우시안 샘플러에 전력·전자기 부채널 취약점이 발견돼 계수 셔플로 방어했습니다. 오버헤드는 **키 생성에서만** 발생하며(+77~112%), 암·복호화는 영향이 없습니다.

## HAETAE — 크기를 줄인 격자 서명

Dilithium과 같은 FSwA(Fiat-Shamir with Aborts) 계열이지만, 고유의 **바이모달 하이퍼볼 거부 샘플링**으로 크기를 줄였습니다.

1. **샘플링 한계 극복** — 기존 방식은 불필요하게 넓은 쌍봉 공간에서 데이터를 추출해 서명이 비대해짐
2. **하이퍼볼 축소** — 가우시안 분포를 이용해 정밀한 '균등 하이퍼볼' 범위 안으로 압축
3. **효율성 극대화** — 안전성 손실 없이 서명 크기를 극적으로 축소

> 🎛 인터랙티브 — 쌍봉에서 구로
> 2D 산점도. 토글 전: +cs, −cs 두 봉우리의 쌍봉 분포(반지름 B). 토글 후: 더 작은 반지름 B′의 균등 원 안에만 점이 남는다.

### 엔지니어링 — 고정소수점으로 부채널 방어
| | 특징 |
|---|---|
| 부동소수점 | 연산 시간에 편차 발생 → 전력·시간 측정으로 비밀키 유추 가능 |
| 고정소수점 | 연산 시간·전력 패턴이 항상 일정한 상수시간 구현 → 부채널 공격 원천 차단 |

복잡한 지수함수 없이 벡터 크기 비교만으로 거부 여부를 판정하므로 구현이 단순합니다.

| 파라미터 | 서명 | 공개키 | Dilithium 대비 |
|---|---|---|---|
| HAETAE120 (Lv.2) | 1,474 B | 992 B | 서명 최대 39%↓ |
| HAETAE180 (Lv.3) | 2,349 B | 1,472 B | 공개키 최대 25%↓ |
| HAETAE260 (Lv.5) | 2,948 B | 2,080 B | |

## AIMer — 격자를 쓰지 않는 영지식 서명

MPC-in-the-Head 패러다임과 전용 일방향함수 AIM을 결합했습니다. **트랩도어가 필요 없는** 접근입니다.

### 핵심 개념 — 머릿속의 다자간 계산
1. **분산** — 서명자가 자신의 비밀(서명키)을 여러 조각으로 나누어 머릿속 5명의 '가상 파티'에게 나누어 준다.
2. **검증** — 외부 검증자는 무작위로 4개의 방만 열어보라고 지시하며 내부 계산 로직을 확인한다.
3. **영지식 증명** — 열린 4개 방의 결과가 완벽히 일치하면, 열지 않은 1개 방(핵심 비밀)을 보지 않고도 서명을 신뢰한다.

> 🎛 인터랙티브 — 다섯 개의 방
> 5개의 문. "검증" 버튼을 누르면 무작위로 4개가 열리고 안의 계산값이 일치함을 초록으로 표시. 닫힌 1개는 "비밀"로 남는다. 여러 번 눌러도 매번 다른 방이 닫힌다.

### 전용 일방향함수 AIM
평문이 병렬 S-box(Mersenne)를 거쳐 선형결합 후 마지막 S-box·평문과 XOR로 가역성을 제거합니다. v1.0은 무차별대입·선형화 공격에 최대 12비트 손상이 있었고, v2.0(AIM2)은 역 Mersenne S-box와 라운드 앞 상수 덧셈으로 원천 차단했습니다.

| 파라미터 | 공개키 | 비밀키 | 서명 |
|---|---|---|---|
| AIMer-I | 32 B | 16 B | 5.9 KB |
| AIMer-III | 48 B | 24 B | 13.1 KB |
| AIMer-V | 64 B | 32 B | 25.2 KB |

공개키·비밀키는 4종 중 가장 작지만 서명은 가장 큽니다. 뚜렷한 시간·크기 트레이드오프입니다.

**엔지니어링**: 저메모리 모드(거대 트리를 저장하지 않고 씨앗 하나에서 실시간 재생성, 수 MB → 수백 B)와 비트 슬라이싱(테이블 참조를 배제한 상수시간 구현)으로 타이밍 부채널을 막습니다.

> 💡 핵심
> KpqC 4종은 NIST와 같은 격자 중심이지만, AIMer가 격자 없는 대안을 제공한다. 공공 조달 기준선이므로 국내 시스템은 두 표준을 함께 고려해야 한다.
