# PQC vs QKD — 소프트웨어와 하드웨어

"양자 암호"라는 말은 두 가지 전혀 다른 기술을 가리킵니다. 이 둘을 구분하지 못하면 잘못된 투자로 이어집니다.

## 두 가지 답

| | 양자내성암호 (PQC) | 양자암호통신 (QKD) |
|---|---|---|
| 정체 | **소프트웨어** — 수학 난제 기반 새 알고리즘 | **하드웨어** — 양자역학 법칙으로 키 분배 |
| 필요한 것 | 일반 단말(PC·폰·서버) + 라이브러리 교체 | 양쪽 끝에 전용 키분배장비 + 전용 양자회선(광케이블) |
| 통신망 | 기존 인터넷·TLS 그대로 | 양자 채널 + 일반 채널의 이중 망 |
| 할 수 있는 것 | 키 교환 + 전자서명 | 키 분배만 (서명 불가) |

> 🎛 인터랙티브 — 두 개의 그림
> 위: 일반 단말 ↔ 일반 단말이 기존 인터넷 선으로 연결, "소프트웨어 업그레이드"라는 라벨.
> 아래: QKD 장비 ↔ QKD 장비가 전용 광섬유(양자 채널)로, 그 옆에 일반 통신망이 나란히 달림. "전용 하드웨어, 거리 제약" 라벨.

> 💡 핵심
> QKD는 보안성이 높지만 하드웨어 기반이라 확장성이 낮고, PQC는 확장성이 높지만 상대적으로 신생. 그래서 백본은 QKD, 종단은 PQC로 역할이 나뉜다.

## QKD는 어떻게 동작하나

양자 키 분배(QKD, Quantum Key Distribution)는 양자역학의 특성을 이용해 암호키를 **물리적으로 안전하게** 나눠 갖는 기술입니다.

| 구성 | 설명 |
|---|---|
| **채널** | 키를 나눠 가질 때는 양자 채널(광섬유·단일 광자), 인증 후 데이터 통신은 일반 채널. 두 회선이 항상 함께 다니는 이중 망 구조 |
| **프로토콜** | BB84 · B92 · EPR. 광자 하나하나의 편광·위상차에 비트를 실어 보냄. 도청자가 광자를 건드리는 순간 양자 상태가 붕괴해 오류율(QBER)이 올라가므로 **도청 시도 자체를 확인** |
| **장비** | 양자 난수 생성기(QRNG)가 예측 불가능한 키 재료를 만들고, 모듈레이터가 그 값을 광자의 편광·위상에 실어 전송. 전자제어시스템이 타이밍을 맞춤 |

### BB84 프로토콜 따라가기

송신자가 임의의 기저로 광자의 편광 상태를 전송하면, 수신자가 선택한 측정 기저와 **일치하는 비트만** 선별해 비밀키를 만듭니다.

| 단계 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 앨리스 난수 비트 | 1 | 0 | 1 | 1 | 0 | 1 | 0 | 1 |
| 앨리스 송신 기저 | + | × | + | × | × | + | + | × |
| 광자 편광 | ↑ | ↗ | ↑ | ↖ | ↗ | ↑ | → | ↖ |
| 밥 측정 기저 | + | + | × | × | × | + | × | × |
| 기저 일치 | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ | ✗ | ✓ |
| 최종 공유 키 | 1 | – | – | 1 | 0 | 1 | – | 1 |

기저가 일치한 비트(1, 1, 0, 1, 1)만 최종 암호키로 승인됩니다.

> 🎛 인터랙티브 — BB84 시뮬레이터
> "광자 보내기" 버튼을 누를 때마다 위 표의 열이 하나씩 채워진다(난수 자동 생성). 8~16개 보낸 뒤 "기저 공개"를 누르면 불일치 열이 흐려지고 공유 키가 아래에 조립된다.
> "도청자 이브" 토글을 켜면 이브가 중간에 측정해 일부 광자 상태가 바뀌고, 앨리스·밥이 샘플 비트를 대조할 때 오류율(QBER)이 올라가 빨간 경고가 뜬다.

## QKD의 한계

| 한계 | 설명 |
|---|---|
| **거리 제약** | 광자는 증폭이 불가능해 중계 없이 약 100 km가 한계. 그 이상은 '신뢰 노드'가 필요하고, 그 노드가 새로운 공격면이 된다 |
| **비용 구조** | 구간마다 전용 케이블과 장비(QKD·암호화기·QRNG)가 필요해 보호 구간을 늘릴수록 비용이 선형으로 증가 |
| **범용망 비호환** | 기존 인터넷 라우팅 위에 얹을 수 없어, 모바일·클라우드처럼 경로가 유동적인 통신에는 적용이 어렵다 |
| **서명 불가** | 키 분배 전용. 채널 인증은 여전히 고전(또는 PQC) 암호에 의존 |

## 세 방식 종합 비교

| 항목 | 기존 암호 (RSA·ECC) | PQC | QKD |
|---|---|---|---|
| 기반 | 소인수분해·이산로그 난제 | 격자·해시·코드 기반 난제 | 양자역학 — 물리 법칙 |
| 양자 위협 | 쇼어에 취약 | 현재까지 유효한 양자 공격 미발견 | 도청 시 양자 상태 교란으로 탐지 |
| 표준화 | 완료, 수십 년 검증 | NIST FIPS 203/204/205 확정(2024) | ITU-T·ETSI 진행 중 |
| 기존 인프라 | 그대로 | 그대로 — 소프트웨어 교체 | 전용 장비·전용 광회선 필요 |
| 전자서명 | 가능 | 가능 | 불가 |
| 통신 거리 | 제한 없음 | 제한 없음 | 실용 100 km 내외 |
| 도입 비용 | 거의 0 | 거의 0 — 개발·검증 공수 | 장비당 고비용 |
| 주요 부담 | 양자 컴퓨터 등장 시 전면 교체 | 키·서명 크기 증가, 성능 오버헤드 | 채널 인증은 고전 암호 의존 |
| 적용 범위 | 현행 전 구간 | 즉시 전 구간 | 백본·기관 간 특수 구간 |

## 양자가 깨뜨릴 수 있는 것 vs 없는 것

| 깨뜨릴 수 있는 것 (양자 취약) | 깨뜨릴 수 없는 것 (양자 내성) |
|---|---|
| RSA, DH 키 교환, DSA, ElGamal | 안전한 키 길이의 대칭키(AES 등, Kerberos 포함) |
| 타원곡선 암호(ECC·ECDSA) | 안전한 해시 길이의 SHA-2·SHA-3 |
| PKI(디지털 인증서·서명) | 격자·코드·다변수·해시 기반 PQC |
| HTTPS/TLS, 다수의 VPN | QKD 프로토콜(BB84·E91 등) |
| HSM, 스마트카드, 다수의 와이파이 보안 | QRNG, 스트림 암호 SHAKE, SNOW 3G |
| 암호화폐 (현행 서명) | 영지식 증명 시스템(일부) |

> 🎛 인터랙티브 — 분류 퀴즈
> 카드 12장(RSA, AES-256, SHA-384, ECDSA, TLS 1.3 기본, ML-KEM…)을 "깨진다 / 버틴다" 두 바구니로 드래그. 놓으면 정답 여부와 이유가 표시.

## 확인해 보기

1. 전자서명이 필요한 시스템에 QKD만 도입하면 충분하다?
   - 정답: 아니오. QKD는 키 분배 전용이며 서명은 PQC(ML-DSA 등)가 필요하다.
2. 클라우드·모바일처럼 경로가 유동적인 통신에 적합한 것은?
   - 정답: PQC. QKD는 전용 회선이 필요해 적용이 어렵다.
