# PQC 학습 사이트 구성 제안

> 참고 모델: [qubit.donghwi.dev](https://qubit.donghwi.dev) — 3D 인터랙티브 요소와 함께 양자 컴퓨터 원리를 단계별로 배우는 사이트
> 원본 자료: 『양자내성암호 기초』(김민지, MegazoneCloud, 2026)

## 1. 왜 이 형식이 PQC에 잘 맞는가

**결론부터: 좋은 방향입니다.** 다만 "양자 컴퓨터 사이트를 그대로 흉내 내기"가 아니라, PQC라는 주제의 성격에 맞게 세 가지를 바꿔야 효과가 납니다.

### 잘 맞는 이유

| qubit.donghwi.dev의 특징 | PQC에 적용했을 때 |
|---|---|
| 한 페이지에 개념 하나, 스크롤하며 단계별로 읽는다 | PQC는 "왜 위협인가 → 무엇으로 막나 → 어떻게 바꾸나"라는 자연스러운 서사가 있어 순차 학습에 적합 |
| 수식 대신 시각적 직관(3D 블로흐 구 등) | 격자·해시 트리·오류정정 코드 모두 그림으로 설명하기 좋은 소재. 발표자료 19쪽의 "미로·파쇄지·용광로·연립방정식" 비유가 이미 그 역할 |
| 「퍼져있는 오해들」 챕터 | PQC도 오해가 많다 ("양자컴퓨터가 모든 암호를 깬다", "QKD면 끝", "Q-Day 오면 그때 바꾸면 된다"). 오해 챕터가 특히 강력 |
| 목차(toc.json)로 챕터를 선언, 페이지는 컴포넌트 | 발표자료 61쪽을 챕터 4개·페이지 11개로 재배치하면 그대로 대응 |

### 바꿔야 할 점

1. **3D보다는 "시뮬레이션·계산기" 위젯이 효과적**
   양자 컴퓨터는 상태(블로흐 구)를 보여주는 게 핵심이라 3D가 맞지만, PQC는 "크기·시간·절차"가 핵심입니다. 키 크기 비교 슬라이더, 정보 수명 vs Q-Day 계산기, BB84 시뮬레이터, KEM 절차 애니메이션이 3D보다 훨씬 이해를 돕습니다. (Three.js 대신 SVG/Canvas + 상태 애니메이션으로 충분)
2. **독자가 다르다**
   참고 사이트는 일반인·학생 대상입니다. PQC 사이트의 실제 독자는 고객사 보안/인프라 담당자일 가능성이 높으므로, 마지막 챕터(전환과 적용)는 "우리 조직은 무엇부터 해야 하나"에 답하도록 실무형으로 씁니다.
3. **발표자료의 영업 정보는 뺀다**
   57쪽 "국내 기업 후보"는 공개 교육 사이트에 올릴 내용이 아니므로 제외했습니다.

## 2. 사이트 구조 (제안)

참고 사이트의 `basic / principle / myth` 3부 구조에 실무 파트 1개를 더해 4부 11페이지로 구성합니다.

| 부 | 라우트 | 페이지 | 원본 슬라이드 |
|---|---|---|---|
| 1. 양자 위협의 이해 | `/threat/1` | 양자 컴퓨터와 오늘의 암호 | 2–4 |
| | `/threat/2` | 쇼어와 그로버 — 무엇이 깨지고 무엇이 버티나 | 5, 7, 10–12, 48–49 |
| | `/threat/3` | Q-Day와 지금 당장의 위협(HNDL) | 6, 8–9 |
| 2. 양자내성암호의 원리 | `/pqc/1` | PQC란 무엇인가 — 네 가지 수학 난제 | 13, 15–19 |
| | `/pqc/2` | 키를 나눠 갖는 법 — ML-KEM | 20–21 |
| | `/pqc/3` | 양자 시대의 전자서명 — ML-DSA · FN-DSA · SLH-DSA | 22–30, 37, 55–56 |
| | `/pqc/4` | 국산 알고리즘 KpqC | 58–61 |
| 3. 전환과 적용 | `/apply/1` | PQC vs QKD — 소프트웨어와 하드웨어 | 14, 31–36 |
| | `/apply/2` | PQC 마이그레이션 4단계와 하이브리드 | 50–54 |
| | `/apply/3` | 국내외 동향과 산업별 적용 | 38–44 |
| 4. 퍼져있는 오해들 | `/myth/1` | PQC에 대한 오해 | 종합 |

각 페이지 MD 파일은 `content/<부>/<번호>.md`에 있고, 목차는 `content/toc.md`에 정리했습니다.

## 3. 페이지 작성 규칙 (MD 파일 공통)

- **frontmatter**: `title`, `description`(목차 카드용 한 문단), `route`, `prev`/`next`
- **본문 구조**: 한 화면에 하나의 아이디어. `##` 하나가 스크롤 한 단락에 대응
- **`> 🎛 인터랙티브`** 블록: 그 자리에 들어갈 위젯의 동작을 설명. 개발 시 컴포넌트 명세로 사용
- **`> 💡 핵심`** 블록: 단락 요약 한 줄. 모바일에서 이것만 읽어도 이해되도록
- **`## 확인해 보기`**: 페이지 끝 퀴즈 2~3문항 (참고 사이트에는 없지만 실무 독자에게 유용)
- 용어는 한글 우선, 영문 약어는 첫 등장에서만 병기 (예: 키 캡슐화 메커니즘(KEM))

## 4. 인터랙티브 위젯 목록 (우선순위순)

| 우선순위 | 위젯 | 페이지 | 설명 |
|---|---|---|---|
| 1 | 정보 수명 계산기 | threat/3 | "이 데이터는 몇 년 비밀이어야 하나" 슬라이더 + Q-Day 추정 연도 → 위험 여부 색상 표시 |
| 2 | 키·서명 크기 비교 막대 | pqc/3 | RSA/ECC/ML-KEM/ML-DSA/FN-DSA/SLH-DSA 크기를 로그 스케일 막대로, 파라미터 셋 토글 |
| 3 | KEM 3단계 애니메이션 | pqc/2 | KeyGen → Encaps → Decaps를 앨리스·밥 캐릭터로 단계 재생, "K는 네트워크를 지나지 않는다" 강조 |
| 4 | 쇼어 주기 찾기 시각화 | threat/2 | a=2, N=21의 a^x mod N 그래프에서 주기 r=6이 반복되는 지점 표시 |
| 5 | 그로버 vs 완전탐색 카운터 | threat/2 | N 슬라이더 → 고전 N/2회 vs 그로버 √N회 숫자·막대 비교 |
| 6 | BB84 시뮬레이터 | apply/1 | 기저 무작위 선택, 일치 비트만 남기기, 도청자 켜면 QBER 상승 |
| 7 | 격자 좋은 기저/나쁜 기저 | pqc/1 | 2D 격자에서 두 기저 벡터를 드래그, 같은 점을 만드는데 "나쁜 기저"로는 얼마나 어려운지 체험 |
| 8 | 위험도 스코어링 표 | apply/2 | 알고리즘 선택 → 점수·등급·전환 기한 표시 |
| 9 | 산업별 조합 추천기 | apply/3 | 업종·데이터 보존기간·기기 제약 선택 → KEM/서명 조합 추천 |

## 5. 기술 스택 제안

참고 사이트와 같은 구성(Vite + React + TypeScript, `toc.json`, 페이지당 컴포넌트)을 권장합니다. 3D가 필요 없으므로 `three.js`/`react-three-fiber`는 빼고, 스크롤 애니메이션(`react-intersection-observer` + `react-spring` 또는 `framer-motion`)과 SVG 차트만 사용합니다. 본문은 MDX로 두면 이 저장소의 MD 파일을 거의 그대로 옮길 수 있습니다.

## 6. 원본 자료 중 보완이 필요한 부분

- 23, 25, 29, 53, 54쪽은 이미지로만 구성돼 텍스트를 추출하지 못했습니다(ML-DSA 개념 1, FN-DSA 개념 1, SLH-DSA 개념 2, 하이브리드 구조 2장). 해당 페이지 MD에는 슬라이드 제목 기준으로 골격만 잡아 두었으니 그림 내용을 보고 채워야 합니다.
- 6쪽의 2026년 Webster et al. (~10만 큐비트) 수치는 arXiv 번호가 자료에 있는 그대로이며 별도 검증하지 않았습니다.
- 13쪽 "2025년까지 4,000큐비트(IBM)"는 과거 로드맵 인용이라 사이트에서는 최신 수치로 바꾸는 편이 좋습니다.
- NIST는 2025년 3월 코드 기반 KEM인 HQC를 5번째 표준 후보로 선정했습니다. 자료에는 없지만 `pqc/1`에 한 줄 추가했습니다.
